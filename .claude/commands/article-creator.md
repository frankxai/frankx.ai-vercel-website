# /article-creator — Evidence to article preview

Use $frankx-content-intelligence. Read its article contract before drafting, then CREATOR.md, AGENTS.md and the applicable source/content instructions. Load $write-like-frankx for copy, $govern-media-fabric for assets, and $frankx-social-studio for distribution candidates.

## Commission
Infer routine choices from the approved brief and existing evidence. Resolve reader job, canonical owner, original contribution, sources, typed claims, useful next action, rights and publication authority. Check existing articles and open PRs before adding a route.

If the central claim lacks evidence, prepare the smallest reporting assignment and hold the article. Never manufacture a founder anecdote or measured result.

## Prepare
Write unpublished material under content/blog/_drafts/ or the established candidate location. Root-level content/blog MDX can be publicly routed; a draft frontmatter flag alone is not a release boundary.

Build and validate the article packet. For programs exceeding three canonical pieces, validate the program packet. Choose the visual tier before production and follow the media contract. Headings, length and FAQs follow the reader's need.

## Review and release
Use an isolated agent branch and a draft PR in frankxai/frankx.ai-vercel-website. Run current repository gates and inspect the preview for the exact commit on mobile and desktop. Record independent findings, corrections and unresolved checks.

Vercel's git integration deploys this repository's main. Follow current publication authority and founder review requirements. Do not call legacy sync-to-production.sh or introduce a second deploy path.

Return the article/candidate, claim and media packets, source revision, actual tests, PR and preview evidence, and next gate. Published status requires source/deployment/live-route confirmation. Stage distribution for the applicable approval.
