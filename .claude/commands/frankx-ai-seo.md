# FrankX SEO workflow

Use /seo-check for provider evidence and technical diagnosis, and /content-strategy for the editorial decision. Both are repository command files; load their contents when the runtime does not expose slash commands.

Activate $frankx-content-intelligence. Read its current SEO/GEO and source-truth references. Use verified properties and live routes; never assume public/sitemap.xml or public/robots.txt owns output in this App Router application.

For each affected canonical page, verify status, canonical, robots, rendered content, descriptive metadata, visible schema agreement, internal discovery, media and a truthful useful next action. Use the established URL and relevant current source. Do not create duplicates for synonymous queries.

Select edits from actual demand and reader problems. Title/description length, heading wording, article length and FAQ count are editorial judgments, not fixed ranking requirements. Keep claims primary-source-backed and date-sensitive facts current.

Recheck current Google Search guidance and incidents. No FAQ-rich-result promises, special AI-schema requirements or Google ranking claims for llms.txt. Citation checks are dated samples, never proof of durable ranking.

Record actual checks, gaps, source/period, canonical ownership and next observation. Prepare focused draft PRs through the repository's current gates; external publication follows the resolved authority.
