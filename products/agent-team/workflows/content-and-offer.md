# One brief → one reviewed package
Keep TEAM.md and your context in one chat. Use a fresh chat for the Reviewer when possible. Each stage stops; there is no scheduled process.

| Stage | You supply / type | You inspect | Save |
|---|---|---|---|
| Brief | TEAM.md + business context; RUN DIRECTOR | Audience, offer, task budget, evidence gaps | brief-v1.md |
| Approve | APPROVE BRIEF v1, then RUN RESEARCHER | Exact claim support and source access | claims-v1.md |
| Choose | CHECK SOURCES v1, then RUN STRATEGIST | Angle, offer bridge, rejected alternative | angle-v1.md |
| Draft | APPROVE ANGLE v1, then RUN CREATOR | Post, offer paragraph, CTA and plan | draft-v1.md |
| Review | Fresh chat: reviewer card + entire packet | Claim-by-claim findings and unresolved checks | review-v1.md |
| Revise | Return findings to Creator; REVISE DRAFT v1 | Corrected copy and changed version | draft-v2.md |
| Recheck | Reviewer checks revised packet | All blockers resolved or still pending | review-v2.md |
| Decide | Apply publication checklist yourself | Final text, links, rights and business terms | final-package.md |

## Concrete first run
Use examples/01-designer.md. Treat its source pack as a fictional exercise. Before giving the worked answer to the model, paste only its brief and evidence. Keep the answer section hidden while you run it. Compare the resulting claims and offer scope to the expected checks. Matching the wording is unnecessary; matching the facts and constraints is essential.

## Sources unavailable
Use the supplied documents and narrow the angle to what those documents support. Mark external claims unresolved. A Researcher can produce a useful evidence audit without web access; it cannot truthfully claim fresh market research.

## When the output is generic
Ask the Director to narrow the audience problem. Give the Creator one real observation and two examples of your writing. Do not add more roles. If the model skips an approval, tell it to stop and return to the last approved artifact. Record this as an intervention in the usability log.

## Finish and repeat
Save the final package locally. Publish manually only after your approval. On the next run, supply measured feedback (views, qualified replies, purchases if any) with dates and denominators. Missing metrics stay unknown. Do not infer sales from attention.
