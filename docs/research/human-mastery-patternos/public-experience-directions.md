# Human Mastery hub — public experience decision gate

Status: **choice required before interface implementation**  
Shared content substrate: the same PatternOS graph, evidence passports, source ledger, and stable URLs power every option.

Only the following three directions are in scope. No public UI has been implemented from this document. Desktop and mobile evidence must both be reviewed after selection.

## Direction A — Evidence Atlas (recommended)

**Promise:** Explore the capabilities and patterns that improve consequential human and human–AI work, with confidence and limits visible at the point of use.

- **Composition:** an orienting thesis, five-plane capability map, Pattern Intelligence loop, then a deep single-pattern reader. Avoid a wall of cards; use a navigable atlas with one dominant detail pane.
- **Primary action:** **Open a pattern.**
- **Proof object:** evidence passport + transfer map + failures/recovery + version history.
- **Typography:** Poppins for decisive wayfinding, Inter for analysis, JetBrains Mono for IDs/passports, Playfair only for a rare human editorial note.
- **Imagery:** original diagrams, evidence contours, transfer paths, and field artifacts; no generic portraits, brains, or “AI glow” stock imagery.
- **Interaction:** filter by capability plane, context, confidence, and validation gap; keep the URL addressable for every pattern. A context switch changes examples without hiding the invariant.
- **Motion:** restrained path reveal and state transition; no animated body copy. Respect reduced motion.
- **Mobile:** replace the atlas overview with a linear capability/loop index and persistent evidence drawer. Never shrink a desktop graph into illegibility.
- **Strength:** makes the proprietary transfer graph legible and credible while fitting the existing research surface.
- **Risk:** can feel academic unless each pattern opens with a concrete decision and field move.

## Direction B — Field Manual

**Promise:** Turn trustworthy ideas into deliberate practice for communication, judgment, creativity, leadership, and execution.

- **Composition:** editorial opening, audience pathways, short field chapters, a focused drill runner, and reflection/outcome log. Reading leads into practice rather than another article list.
- **Primary action:** **Start a field drill.**
- **Proof object:** source → drill → scoring rubric → observed outcome → next repetition.
- **Typography:** Playfair for chapter openings, Inter for instruction and evidence, Poppins for navigation, JetBrains Mono for timing, scores, and object IDs.
- **Imagery:** annotated workshop boards, speaking marks, decision traces, before/after artifacts, and original line illustrations.
- **Interaction:** choose a context and time budget, run a drill, score observable behavior, then compare attempts. Reflection is optional and private by default.
- **Motion:** page-turn or progress cues only where they clarify sequence; no gamified confetti.
- **Mobile:** single-task drill mode with thumb-reachable timer, one instruction per viewport, and offline-safe draft capture.
- **Strength:** connects books and research to behavior quickly and supports Academy/workshop products.
- **Risk:** may hide the cross-domain graph and be mistaken for a conventional course library.

## Direction C — Pattern Console

**Promise:** Compile a bounded human–AI operating protocol for the decision in front of you.

- **Composition:** dense professional workspace with context input, candidate patterns, role/authority matrix, compiled protocol, exception ledger, and run history.
- **Primary action:** **Compile a protocol.**
- **Proof object:** explicit human/AI roles + irreversible-action gates + predeclared metric + exception/recovery log.
- **Typography:** Inter for workspace UI, JetBrains Mono for protocols and logs, Poppins for mode changes; Playfair is omitted inside the console.
- **Imagery:** none unless it is an operational artifact. Hierarchies, paths, and timelines are rendered as exact diagrams.
- **Interaction:** progressively reveal complexity; allow manual edits to every AI suggestion; require human confirmation for values, consent, and irreversible moves.
- **Motion:** functional state changes, diff highlights, and run progress only. Logs remain stable while new events arrive.
- **Mobile:** companion review/approval surface, not a compressed authoring console; protocol construction remains desktop-first.
- **Strength:** makes PatternOS an applied human–AI runtime and supports a high-value team product.
- **Risk:** premature product complexity before patterns, assessments, and outcome instrumentation have earned trust.

## Decision rule

Choose one launch shell:

- Select **A** if the next objective is public authority, discoverability, and an inspectable moat. This is the recommendation.
- Select **B** if the next objective is practice adoption, workshops, and book-to-behavior conversion.
- Select **C** if a committed design partner is ready to test consequential human–AI team workflows.

After selection, the release sequence is: capture the chosen desktop and mobile context → approve hierarchy and primary action → implement one vertical slice → verify accessibility, evidence rendering, mobile rhythm, and Vercel preview → expand. Until then, the interface gate remains closed.
