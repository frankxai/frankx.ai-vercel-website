# AI Architect content wave release record

## Experience thesis

For founders, creators, product leaders, and small expert teams trying to turn AI leverage into durable agency, this release connects two decisions that are usually treated separately: how the founder redesigns work, and how a generated product becomes an owned, governed business asset. The intended feeling is clarity and controlled momentum—not tool anxiety, effortless-income theater, or a catalogue of affiliate offers.

The release contains two new canonicals:

- `/blog/4-hour-ai-architect-deal-framework-2026` rebuilds every chapter of DEAL for governed AI and human delegation.
- `/blog/best-ai-app-builders-2026` separates app builders, repository agents, workflow runtimes, models, production platforms, and business systems, then defines the handoffs between them.

## Direction decision

Exactly three visual and editorial directions were developed before implementation:

1. **Control Plane / Graduation Path — selected.** Deterministic architecture drawings turn both articles into operating instruments. The DEAL map shows Definition, Elimination, Automation, and Liberation as a closed loop with evidence and exceptions. The builder map shows the graduation path from validated intent to an app builder, owned source, code-agent review, release, business systems, and measured outcomes. This direction was selected because it teaches the decision, survives mobile cropping, avoids unsupported product rankings, and matches the FrankX AI Architect position.
2. **The Tool Shelf — not selected.** A high-density logo grid would have made vendor recognition immediate, but it would flatten unlike categories, create trademark and freshness debt, and make an editorial comparison look commercially determined. Product names remain nominative HTML text; no third-party logos enter the art.
3. **The Futurist Office — not selected.** A cinematic scene of AI employees, holographic assistants, and a liberated founder could have created more visual drama. It was rejected because it would turn a governance argument into speculative lifestyle advertising and introduce unnecessary likeness, representation, and accessibility risk.

The selected direction uses original repo-native SVG, live HTML typography for article content, an obsidian field, emerald/cyan system paths, and restrained warm markers for exceptions. It deliberately avoids robots, generic AI brains, stock people, fake dashboards, book-cover imagery, vendor logos, and readable text generated by an image model.

## Evidence and commercial policy

- Chapter mapping is grounded in Tim Ferriss's official tools and retrospective material.
- Productivity claims are presented as task- and context-dependent, with peer-reviewed/experimental evidence and METR's counter-evidence for experienced software developers.
- Builder capability statements use official product documentation and are dated to 27 August 2026.
- The builder article explicitly states that it is a capability-and-architecture comparison, not a controlled bakeoff.
- No unverified `?ref=` or invented core-provider affiliate links are used.
- No affiliate route is published in this wave. The two available redirects resolve to partner-program application pages, not issued customer-referral destinations, so they are held until the providers supply valid attribution URLs.
- The book title and product names are used nominatively. No third-party cover, author likeness, logo, or product screenshot is reproduced.

## Baseline and release verification

The current FrankX article template was inspected on production before implementation at a 1363×936 desktop viewport. The baseline established the reusable page contract: dark editorial shell, restrained header chrome, live title and metadata, large hero media, readable MDX body, callouts, tables, and diagram components. This release changes content and governed media only; it does not introduce a new article layout or global design-system dependency.

Pre-merge gates:

- **Passed locally:** frontmatter, MDX compilation, both article-packet validators, source/claim ledgers, internal-link static analysis, visual manifests, and JSON syntax.
- **Passed locally:** type checking, linting (zero errors; seven pre-existing warnings), strict claim audit, strict AI-slop audit, and a complete production build of 1,381 pages.
- **Passed independently:** truth/rights, editorial voice, canonical ownership, affiliate treatment, technical claims, and visual usability.
- Inspect both new routes on the Vercel pull-request preview at desktop and mobile breakpoints, including horizontal table/diagram behavior and reduced-motion-safe rendering.

The repository's aggregate `links:check:ci` wrapper could not bind its default development-server host in this isolated runtime. Its underlying static checker passed all 2,625 files, and both new routes returned `200` with the expected `www` canonical, FAQ structured data, and OG image when checked against the production build on `127.0.0.1`. The Vercel preview remains the authoritative rendered-route and live-link gate. A broader local crawler also surfaced pre-existing failures on `/music`, `/library`, and `/rss.xml`; those legacy routes are outside this release and are not represented as fixed here.

Post-merge gates:

- Confirm the Vercel production deployment is `READY` for the merged Git commit.
- Verify both canonical URLs return rendered HTML and the expected title, canonical, structured data, hero, diagram, and internal links.
- Check production console/runtime errors and add a deployment receipt to the pull request.

The pre-merge production commit will be recorded in the pull request and deployment receipt. If either live route fails a production gate, revert the merge through GitHub so Vercel's native Git integration creates an auditable rollback deployment.
