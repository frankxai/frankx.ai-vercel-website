# Browser tools: public FrankX content

State: implementation candidate; not merged or live-verified.

Scope: adapt the existing /api/mcp public read surface to browser agents. Owner: FrankX engineering. User job: find an article, read its paginated source and inspect product-page links without guessing routes.

Base: e91d6da072460ecfd460d0d04f445f678fb77a51.

The root layout adds one null-rendering client component. It registers frankx_search_site, frankx_get_article and frankx_list_products. Existing server handlers, rate limits and validation remain in force. The adapter permits only same-origin read tools, rejects redirects, bounds requests and responses, matches JSON-RPC response IDs, imposes a deadline and revokes tools on unmount. Content results are untrusted data. No write, checkout, credential or private-account tool is exposed.

Validation: 32 MCP, adapter and descriptor integration tests pass; full repository typecheck, changed-file lint and strict editorial audit pass. Full production build was killed in this environment; it is not recorded as passing. Live endpoint fetch and rendered-browser checks could not complete here. The browser bridge uses MCP 2025-11-25, as supported by the installed server SDK. An end-to-end test through the real HTTP handler caught and now prevents a newer-protocol 400 failure. The existing test:mcp CI command now includes the new tests. Independent exact-head review, required CI, preview and production checks remain open.

Guidance: WebMCP imperative API and Modern Web Guidance progressive enhancement. Unsupported browsers retain normal browsing. No CSS, animation, public copy, dependencies or model calls change.

Known maintenance: browser input descriptors mirror the existing public server schemas; schema changes must update both and their contract tests.
