# Information architecture and sitemap

**State:** proposal, 5 November 2026. No URL is renamed, merged or removed by anything here. Prominence and cross-links only. Evidence and the full route tiering: [audits/03](audits/03-ia-nav-sitemap.md).

## The facts that constrain the menu

- 221 real route directories; 1,077 routes in `data/route-index.json`; 288 blog files; 33 records in `data/products.json`.
- Desktop and mobile menus are hand-duplicated registries (`components/NavigationMega.tsx`, `components/MobileNavOverlay.tsx`). Five doors in this order: Founder, Build, Learn, Create, Music. 67 items. No images.
- Two tests pin the menu: `scripts/tests/navigation-completeness.test.mjs` (every item survives grouping once; the Founder door keeps `/magic /vault /ecosystem /map /qualities /intelligence-atlas /licensing`) and `scripts/tests/navigation-mobile-contract.test.mjs` (door order, labels, dialog and focus-trap attributes, no `uppercase` in menu headings). Music stays its own door: PR #409 demoted it and that was reversed.
- Missing from every menu: `/llm-hub`, `/agent-team`, `/start`, `/for/creators`, `/opus-pro`, `/youtube`. "AI Studio" and "Consulting" point to one destination.
- No first-party traffic data is in the repository. The only demand signal is Semrush US volumes from 20 August 2026 (ai architecture 2,400; ai architect 1,600; mcp server 40,500; llm gateway 720 at KD 23). Door order should be confirmed against 90 days of Search Console and GA4 before it is final.

## Three directions

### A. Five doors, made visual

Keep the five doors and their test pins. Each panel gets one image tile, five featured destinations with a one-line promise, and a "See everything" index generated by `resolveNavigationGroups` so nothing is lost. Add Agent hub and LLM hub to Build; collapse Consulting into Work with Frank.

- Wins: smallest diff, no test changes beyond content.
- Loses: research and evidence stay inside the Founder door, where a reader looking for proof will not look.

### B. Six doors with Research (recommended)

Founder, Build, Research, Learn, Create, Music. Research becomes a door because evidence is the site's strongest asset and the clearest frontier-tech signal.

- Wins: the frontier position is proven in the menu itself; the SEO entry points (research, blog, signals) get a home; the Founder door shrinks to founder work.
- Costs: the mobile contract test's door order changes in the same PR; one more decision in the header.

### C. Intent-led doors

"Run a company with agents", "Build with AI", "Make things", "Read the evidence", "Listen". Each door is a situation, not a department.

- Wins: the plainest language for all three readers, including people new to the vocabulary.
- Loses: breaks most pinned labels (`Founder`, group names), long labels crowd the header at 1024px, and it conflicts with the shipped founder pivot.

**Why B wins:** it is the only direction that puts the evidence in the header without discarding the rulings already encoded in tests (Founder door, Music door). A keeps the problem; C wins on language but costs more contract churn than the gain justifies. C's situation phrasing survives inside B as the promise line on each destination.

## Direction B, specified

Panel layout at 1024px and above: left, one image tile (4:5, from the visual system's nav-tile class) with the door's promise; middle, three to five destinations, each a title and one plain sentence; right, one proof chip pointing at a real artifact; bottom, "See everything in <door>". Mobile keeps the existing dialog and focus trap; tiles become the first row of each section view.

Personal and family routes (`/papa`, `/familie`, `/opa-und-oma`, `/lebensbaum` and the rest) stay out of the main menu and reachable as they are today. The contemplative register (`/rails`, `/canon`, `/soulbook`) is not flattened.

## Cross-link rules for duplicate clusters

| Cluster | Rule |
|---|---|
| `/ai-architecture`, `/ai-architect`, `/ai-architect-academy` | Pillar is `/ai-architecture` (Build door). The academy owns "ai architect" in Learn. The pillar links `/ai-architect` as "Run the review yourself". |
| `/agents`, `/agent-hub`, `/agent-team`, `/llm-hub`, `/acos` | One Build group, "Agents and models". `/acos` links `/agent-team`. |
| `/founder-stack`, `/stack`, `/build` | Only `/founder-stack` in the menu. `/stack` is reached from Shop and Resources as "Tools I use", with a line that separates it from the diagnostic. |
| `/partners`, `/partnerships`, `/affiliates`, `/allies` | "Collaborations" goes to `/partnerships`; `/allies` sits under it; `/partners` and `/affiliates` stay in footer and disclosure surfaces, rendered from `data/affiliate/programs.json`. |
| `/research`, `/insights`, `/intelligence-atlas`, `/signals`, `/intelligence-system` | Research door. `/insights` is linked from Research as "Essays". `/intelligence-system` gains one line saying it is about investing. |
| `/start`, `/start-here` | `/start` is the single door; `/start-here` is one route inside it. |
| `/products`, `/shop`, `/templates`, `/ai-architecture/templates` | `/products` is the landing; `/shop` is the store; the two templates pages carry distinct labels: "Starter kits" and "Architecture templates". |

## Implementation contract (direction B)

1. One dedicated PR. Never combined with homepage work.
2. Update both nav tests in the same PR, labelled `[contract-change]`, with the reason.
3. Edit both registries in place first; consolidating them into one module is a separate, optional PR.
4. Gates: `pnpm run type-check`, `pnpm run lint`, `pnpm run ai-slop:audit:strict`, `pnpm run build`, `pnpm run merge:gate`, `node --test scripts/tests/navigation-*.test.mjs`, web-release-gate evidence at 375, 768 and 1440 with keyboard and reduced motion.
5. Image tiles come from approved assets only (see [VISUAL-SYSTEM.md](VISUAL-SYSTEM.md)); a door with no approved tile ships with its proof chip alone.
