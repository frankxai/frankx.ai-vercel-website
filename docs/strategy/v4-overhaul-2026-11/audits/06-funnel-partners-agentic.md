## 4. Agentic surfaces
- /ask: static Q&A directory (data/ask-questions.ts, FAQ JSON-LD). No chat.
- /agent-hub: server-rendered registry (lib/agent-hub/registry, data/agent-registry.json) of external agents; no chat. /agents, /agent-team: static pages. /llm-hub: model comparison (data/llm-models.json). /command-center: client dashboard (admin-style). /workspace: static case study page (featuredWorkspaceCase). /acos: static, uses FrankOmega.
- components/FrankOmega.tsx (221 lines): only a mascot avatar/mood component (images in /images/mascot); used on 404 and /acos, /frankx. No chat logic.
- Chat endpoints: app/api/byok/chat/route.ts - bring-your-own-key proxy to Anthropic (claude-sonnet-4-20250514), OpenAI (gpt-4o), Google (gemini-2.0-flash) via raw fetch; used only by app/prototype/chat-playground (the visitor pastes their own key). app/api/agents/route.ts: canned persona map, no model. So there is NO hosted "Frank's AI" chat today.
- Runtime/provider: `ai` ^6.0.190 is installed (no @ai-sdk/* provider packages). Hosted use is through the Vercel AI Gateway with plain "provider/model" strings via lib/ai/gateway-client.ts (default anthropic/claude-haiku-4-5 for the 404 agent, AI_GATEWAY_404_MODEL) and lib/swarm/executor.ts (admin-only council at /api/swarm/run, results in Vercel KV). No OpenRouter, no direct Anthropic SDK.
- Auth: next-auth 5 beta with a single admin credentials provider (ADMIN_EMAIL, ADMIN_PASSWORD_HASH, NEXTAUTH_SECRET); app/auth/signin is admin only. No Clerk, no Supabase auth, no @supabase/* dependency or client in the repo (Supabase appears only as a URL for the growth-capture edge function and in text).
- Env a hosted chat would need: AI_GATEWAY_API_KEY (or VERCEL_OIDC_TOKEN on Vercel), KV_REST_API_URL/TOKEN for rate limit + history (rate limiting exists in kv), optionally NEXTAUTH_SECRET. For member accounts: add Supabase (NEXT_PUBLIC_SUPABASE_URL, publishable key, server key) - not present.
- "eve": appears only as content about Vercel's eve (Agent Stack, public beta) in content/blog/vercel-ship-2026-builder-decisions.mdx and content/guides/{vercel,vercel-ai-sdk,vercel-ship-2026-recap}.mdx. These guides explicitly say do not standardize on eve until GA. No code uses eve; no "eve" runtime in lib/ or app/.
- Problems: (1) no hosted chat despite 8+ "agent" pages, so the surface promises more than it delivers; (2) /api/byok/chat and playground use outdated model IDs and raw fetch, unauthenticated; (3) no abuse protection design (rate limit, cost cap) for an anonymous public bot.
- Smallest fix: one /api/ask-frank route using ai streamText through the Gateway (anthropic/claude-haiku-4-5), grounded on data/ask-questions.ts + llms-full.txt, IP rate limit in KV, no auth, no memory; mount as a panel on /ask. Defer Supabase auth and eve.
