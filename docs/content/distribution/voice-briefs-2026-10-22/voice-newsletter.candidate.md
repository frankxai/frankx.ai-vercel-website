File paths are poor material for dictation. One wrong character can change the file an agent opens, the command it runs or the value it uses.

Voice is useful for the part of a brief that benefits from explanation: why the task matters, what you already know, which attempt failed, what the reader needs. Keep the exact references in a block you type after speaking.

Here is a small structure to try on your next coding task:

ROLE: Who is responsible for this task?
GOAL: What should exist when the work is done?
CONTEXT: Why does it matter, and what is already known?
CONSTRAINTS: What must remain true?
DONE WHEN: Which observable conditions establish completion?
VERIFY: Which checks will provide the evidence?

The useful test is one real task. Keep a record of clarifying questions, corrections and whether the first result meets the brief. A faster transcript alone does not establish a better handoff.
