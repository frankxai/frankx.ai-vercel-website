# Apify resource: experience and visual decisions

Recipient: a technical founder choosing an interface for bounded page research.
Job: inspect equivalent requests, carry evidence forward and understand the cost
assumptions before authorizing an execution. The primary action is the offline
workbench/download. No account creation, payment or data collection is required.

## Context and selection

Host `/blog` was inspected in the live cloud browser before implementation, at
wide desktop and at a narrow CSS viewport. The browser does not expose device
emulation; Chrome page zoom supplied the observed narrow CSS layout (454 × 312,
DPR 3, 300% zoom). That observation is responsive browser evidence, not a claim
of a physical-phone or 390 × 844 test. Baseline screenshots were observed in the
session; no content-addressed capture file is asserted here.

Exactly three directions were compared before implementation:

| Direction | Composition, type, image and interaction | Decision |
| --- | --- | --- |
| Annotated evidence observatory | Existing editorial header; cinematic glass and paper still life; precise architecture with solid/dashed boundaries; inspectable requests and cost assumptions; no entrance motion | Selected for editorial warmth and a useful technical instrument |
| Run desk | Monospace-led instrument panel; controls and terminal as the main visual; little narrative art; state changes only | Rejected: too austere for the article |
| Field notebook | Warm notebook spread; serif margin notes and human research imagery; annotated source cards; light page transitions | Rejected: less immediate clarity about the interface decision |

This is a maker selection. It does not stand in for an independent visual verdict.

## Implemented roles

Hero and OG use one original AI-generated still life. It is explicitly a metaphor,
with no vendor logo, product screenshot, fabricated run or graph. Exact architecture
and comparison remain native HTML/text. Existing source uses solid boundaries;
proposed Apify integration uses dashed boundaries and amber labels. Workflow
behavior is demonstrated by inspectable requests and a blank evidence receipt.

The narrow composition keeps source labels and diagram text at reading size,
wraps interface controls, uses vertical architecture flow and scrolls JSON locally.
The wide composition pairs the two execution choices and evidence/review stages.
No separate agent cast, new typography system, animation dependency or background
video was introduced. Existing site fonts and token rules remain authoritative.
No new animation is shipped; state confirmation is immediate and reduced-motion
users receive the same working information. The existing shared image viewer's
behavior is outside these two new components.

## Interaction and privacy

The component imports a generated plan from the tested offline planner. It makes
no Apify request, reads no credentials and accepts no target URLs. JSON copy and
save controls preserve synthetic labels. Cost inputs are local state; blanks
retain unknown values. No rates or calculator outputs represent live usage.
Only fixed action/interface/content labels go through the existing privacy-safe
analytics helper on successful copy/download. No entered cost, URL, token,
clipboard content or receipt field is sent in those events. Do Not Track and the
existing consent policy remain authoritative. Marketing conversions are untested.

Affiliate navigation uses the existing registry, `AffiliateLink` and `/go/apify`.
Freshness expiry falls back through the shared resolver. The issued referral is
explicitly disclosed at the article opening and at its call to action.
