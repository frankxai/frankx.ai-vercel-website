# Expert Authority Intelligence Prompt Pack

Use these prompts sequentially. Do not begin with content generation or funnel tactics before the evidence, canon, and authority position are established.

## 1. Expert Canon Extraction

```text
Act as an expert-canon architect.

INPUTS
- Biography, career chronology, books, talks, transcripts, notes, courses, offers, testimonials, and client outcomes.

TASK
Build a governed expert canon. Identify:
1. recurring decisions and trade-offs
2. explicit and implicit methods
3. mechanisms explaining why the methods work
4. contrarian beliefs and category assumptions
5. diagnostic questions
6. stories, turning points, failures, and identity-forming moments
7. demonstrated proof and unsupported claims
8. phrases that should remain verbatim
9. contradictions, outdated positions, and missing evidence
10. boundaries: what this expert does not claim or serve

OUTPUT
- Evidence ledger with provenance and confidence
- Principles
- Decisions
- Methods
- Mechanisms
- Diagnostics
- Stories
- Proof stack
- Language bank
- Contradictions
- Missing evidence
- Claims prohibited until stronger proof exists

RULES
- Cite the source for every important claim.
- Preserve contradictions rather than smoothing them away.
- Separate operator belief, audience perception, and demonstrated outcome.
- Do not generate positioning, products, or content yet.
```

## 2. Audience Signal Graph

```text
Act as an audience-intelligence analyst.

INPUTS
- Discovery calls, sales calls, comments, direct messages, support tickets, surveys, quiz responses, webinar chat, search data, email replies, churn reasons, refunds, and non-purchase notes.

TASK
Cluster the evidence by:
- desired outcome
- triggering event
- current workaround
- perceived obstacle
- emotional consequence
- economic consequence
- objection
- urgency
- awareness level
- willingness to pay
- segment
- exact language

Calculate an opportunity score from 1–5 for each factor:
urgency × consequence × access × expert-proof-fit × willingness-to-pay

OUTPUT
- Segment map
- Problem clusters
- Evidence count per cluster
- Representative verbatim language
- Opportunity score
- Existing alternatives
- Buying triggers
- Objections
- Disconfirming evidence
- Problems that are frequent but commercially weak
- Top three commercially viable opportunities

RULES
- Do not equate mention frequency with commercial value.
- Keep verbatim language separate from interpretation.
- Surface contradictions between what people say, do, and buy.
```

## 3. Authority Position Synthesis

```text
Act as an authority-position strategist.

INPUTS
- Governed expert canon
- Audience signal graph
- Existing market alternatives and category language

TASK
Generate no more than three candidate positions. Each must define:
- ideal buyer
- triggering event
- costly problem
- rejected alternatives
- differentiated point of view
- named mechanism
- proof stack
- strategic exclusions
- category language
- content pillars
- claims permitted now
- evidence required for stronger claims

Score each candidate from 1–5 on:
- market urgency
- expert credibility
- proof density
- recognizability
- defensibility
- product depth
- distribution fit

OUTPUT
1. comparative decision table
2. selected position
3. one-sentence category definition
4. authority statement using:
   This is the obvious expert for ______ when ______ because ______.
5. named mechanism and explanation
6. proof hierarchy
7. claims not yet permitted
8. content territory
9. reasons the rejected positions lost

RULES
- Optimize for recognizability and defensibility, not breadth.
- Select one position.
- Do not use vague abstractions that cannot govern product or content decisions.
```

## 4. Product Stepladder Architecture

```text
Act as a product-intelligence architect.

INPUTS
- Selected authority position
- Named mechanism
- Audience segments and buyer states
- Existing proof, delivery constraints, and price history

TASK
Construct one stepladder:
1. free diagnosis
2. paid activation
3. systemization product
4. core transformation
5. premium implementation
6. optional continuity or intelligence layer

For every tier specify:
- buyer state before purchase
- triggering event
- promised transition
- mechanism
- inputs
- deliverables
- time-to-value
- completion event
- evidence generated
- delivery model
- operator effort
- gross-margin assumptions
- price rationale
- objections
- non-fit criteria
- next purchase and why it is logically next

For courses, define each module by:
- prior buyer state
- capability gained
- minimal concept required
- action performed
- artifact produced
- feedback mechanism
- proof of completion
- prerequisite for the next module

OUTPUT
- Product ladder table
- Core-offer specification
- Course or cohort architecture
- Price rationale
- Cross-sell map
- Evidence-generation plan
- Minimum production release

RULES
- One mechanism governs the whole ladder.
- Cross-sells solve the next constraint; they do not add unrelated information.
- Reject modules that transfer information without changing capability or producing evidence.
```

## 5. Traffic-to-Revenue Learning Loop

```text
Act as a funnel-intelligence and growth-systems architect.

INPUTS
- Authority position
- Product ladder
- Audience segments
- Existing content, traffic, conversion, email, and sales data

CHANNEL ROLES
- LinkedIn: argument, operator judgment, category language, and proof
- YouTube: depth, demonstration, transformation, and trust
- Instagram: identity, reach, emotional recognition, and social proof

TASK
Route every channel into one diagnostic. Segment leads by weakest engine, buyer state, urgency, and commercial fit.

Design:
- content-to-diagnostic paths
- diagnostic scoring and result pages
- free skill or agent delivery
- webinar, challenge, or quiz selection logic
- segmented email sequences
- entry-product conversion
- core-offer conversion
- cross-sell and ascension
- retargeting
- attribution
- experiment backlog
- evidence write-back into the expert canon, audience graph, and product system

For each funnel stage define:
- source
- segment
- promise
- experience or artifact
- primary metric
- drop-off threshold
- follow-up logic
- next best action
- experiment owner
- hypothesis
- stop condition
- evidence returned to the system

OUTPUT
- Traffic-to-revenue map
- Diagnostic branches
- Webinar / challenge / quiz decision
- Email sequence architecture
- Cross-sell map
- Measurement contract
- First ten experiments ordered by expected information value

RULES
- Do not create separate funnels for each social channel.
- Do not send every lead the same sequence.
- Every experiment must have a hypothesis and stop condition.
- Favor information gain over vanity metrics.
```

## 6. Seven-Day Production Release

```text
Act as the release architect for the Expert Authority Intelligence System.

Using all prior artifacts, define the smallest production release that can collect real evidence within seven days.

The release must include:
- one public landing page
- one diagnostic
- personalized result logic
- email capture and segmented tagging
- one free skill or agent
- one founding paid offer or application
- one channel-specific launch asset for LinkedIn, YouTube, and Instagram
- analytics events
- operator notification
- experiment ledger
- human approval gates

Return:
1. release scope
2. route and component map
3. data model
4. event taxonomy
5. content assets
6. offer copy
7. test plan
8. deployment checklist
9. first 25 participants target
10. decision rules for the next version

Constraint: reject anything that does not improve participant value, evidence quality, conversion learning, or delivery readiness.
```

## 7. One-Prompt Full Run

```text
Build my Expert Authority Intelligence System from the supplied expert and audience evidence.

Execute in this order:
1. evidence ledger
2. expert canon
3. audience signal graph
4. authority-position candidates and selection
5. named mechanism
6. product stepladder
7. course architecture
8. traffic-to-revenue learning loop
9. agent and automation design
10. seven-day production release

Cite evidence, preserve contradictions, separate demonstrated outcomes from aspiration, and refuse unsupported claims. Select one authority position and one product mechanism. Route LinkedIn, YouTube, and Instagram into one segmented diagnostic. Every product and funnel step must produce evidence that updates the system.

Finish with:
- executive decision
- final artifacts
- unresolved human decisions
- 30-day operating cadence
- exact next release
```
