# Experience blueprint — support triage

One table per flow in `02-user-flows.md`. Every stage named there is a row here, failure stages
included, and every row has a Human cell even when the honest answer is "none".

## Flow 1 — inbound ticket triage and drafted reply

| Stage | Human | AI/Agents | Systems |
|---|---|---|---|
| Ticket arrives | None — the customer sends an email | None yet | Support platform intake webhook, worker queue (`apps/worker/src/queue.ts`) |
| Classify and route | None on the default path | Classifies urgency and picks one of the four queues; writes the route to the ticket | Support platform API, queue definitions (`fixtures/queues.yaml`) |
| Retrieve macros | None | Retrieves up to three approved macros for the classified topic | Managed vector store (`apps/worker/src/index-macros.ts`) |
| Draft reply | None | Drafts a reply and attaches it as an internal note; holds no send capability | Support platform ticket notes |
| Agent review | Support agent for the destination queue reads route and draft, edits or discards | No further action; the draft does not change while it waits | Support platform UI |
| Send | Support agent clicks send — this is the approval gate | None; the system cannot send | Support platform outbound mail |
| Feedback | Support agent tags a bad draft | Tag is collected, not applied to behaviour | Ticket history, weekly review list |
| Failure: confidence below floor | Support agent picks the queue by hand | Stops before drafting; writes "not classified — confidence below floor" | Escalation queue, support platform notes |
| Failure: vector store unavailable | Support agent reads a draft labelled as macro-less and decides whether to trust it | Drafts from the ticket alone and labels the omission | Support platform, vector store health check |
| Failure: model provider unavailable | Support lead is emailed at queue depth 50 and the team works the inbox by hand | Retries three times, then leaves the job queued | Worker queue, mail to the support lead |
| Failure: no review within four hours | Support lead sees the ticket on the stale-review list | None — the draft stays as an internal note | Support platform SLA view |

## Flow 2 — nightly macro re-index

| Stage | Human | AI/Agents | Systems |
|---|---|---|---|
| Re-index starts | None — fully unattended, reported next morning | Diffs the macros directory against the stored digest | Scheduler, macros directory, digest store |
| Embed changed macros | None | Embeds only changed macros | Embedding endpoint, vector store write path |
| Swap index | None | Promotes the new namespace, keeps the previous one for one day | Managed vector store namespaces |
| Report | Platform engineer reads the job log line the next morning — review, not approval | Appends counts and duration | Job log |
| Failure: partial embed | Platform engineer sees "index swap skipped — partial embed" | Refuses to promote a partial namespace | Job log, vector store |
| Failure: corpus above modelled size | Platform engineer re-runs the cost model in `04-roi.md` | Records corpus size against `fx.corpus` | Job log, `00-frame.md` assumptions |

## Flow 3 — weekly eval review

| Stage | Human | AI/Agents | Systems |
|---|---|---|---|
| Collect tagged tickets | Support lead opens the weekly list | Lists tickets tagged `bad-draft` from the last seven days | Support platform search |
| Promote to cases | Support lead chooses what becomes a permanent expectation — nothing is promoted automatically | None | `06-evals/cases.jsonl` |
| Run harness | Support lead runs one command from `07-runbook.md` step 5 | Executes each case against the real entry point | Eval harness, worker entry point |
| Decide | Support lead decides whether behaviour changes this week | None | `review.md`, change process |
| Failure: promoted case fails | Support lead leaves it red and records it in `review.md` | None | Harness output |
| Failure: review not run | Support lead sees the stale run date | None | `06-evals/rubric.md` run log |

## Irreversible actions, cross-checked against the trust boundary

Every stage whose AI/Agents cell could touch one of the eight human-gate categories, checked
against `05-trust-boundary.md`:

| Stage | Category | Human cell holds the gate? |
|---|---|---|
| Send | `external_send` | Yes — the support agent clicks send, and the system holds no send tool at all |
| Swap index | `destructive` | Partly — promotion is automatic, and the rollback is that the previous namespace is retained for one day. Recorded as an accepted risk in `05-trust-boundary.md`, not as a gate |
| Draft reply | none | Not irreversible; the draft is an internal note |
