# ADR-0003: Memory is written only by a human promotion step

## Status

Accepted

## Context

The point of a personal system is that it remembers. The risk of a personal system is that it
remembers something wrong: a fact promoted from a summary of a web page, quoted confidently in
every later brief, with the original source three hops away. Nothing in the daily loop can catch
that, because the loop is where it came from.

There is also a T3 path directly into memory: a note the operator pasted in from a page they were
reading is a local file, and looks exactly like a note they wrote themselves.

## Decision

Only the evening ledger's promote step writes to `~/.coe/memory/`. Candidates are proposed with
their source, capped at seven per night, and accepted one at a time by the operator. No loop
promotes. `delete_memory` requires the memory id echoed back in the same session. The store is the
source of truth and the index is derived, so a partial write is repaired by a rebuild rather than
by reconciliation.

## Consequences

Easier: the memory store's provenance is complete — every entry has a source and a date on which a
person accepted it. Poisoning requires a human to click accept on a specific proposal, which is a
much smaller attack surface than "anything the loop found convincing".

Harder: promotion is a nightly chore, and the second kill criterion in `00-frame.md` exists because
a chore that costs more than it saves is the likely failure mode.

Open risk: the operator can accept seven candidates without reading them. The cap and the weekly
review are mitigations, not controls — recorded as finding F2 in `05-trust-boundary.md` rather than
claimed as solved.

## Alternatives considered

| Alternative | Why not |
|---|---|
| Loops write memory directly | The system's confident wrong fact becomes permanent with nobody in the path; the most expensive failure mode with the least friction |
| Confidence threshold on auto-promotion | A threshold on a model's own confidence is the model grading itself, which is what evals exist to avoid |
| No long-term memory at all | Removes the recall problem the system exists to solve (`01-discovery.md` § 1) |

## Trust boundary

Memory is T0. Candidates can be derived from T3 content, so each candidate carries its source and
the promote prompt shows it. A candidate whose source is a fetched page is shown with its URL, so
"where did this come from" is answerable at the moment of acceptance rather than three months later.
