# Frame — personal AI centre of excellence

## fixture notice

This is a worked example distributed with the AI Architect plugin. The operator, the machine, the
file paths, the volumes and the command outputs below are a **fixture**: they are stated here as
the example's definition, not recorded from a live machine. The artifact set is internally
checkable — every number in `04-roi.md` re-derives from `prices.json` and the assumptions in this
file — and it is not evidence about anyone's real setup. Re-derive everything against your own
machine before treating a line here as evidence.

## outcome

One person's routine reading, sorting and recall runs as three scheduled loops on their own
machine, and every output is a draft that person reads before it becomes a decision.

## non-goals

- Serving anything to anyone else. No API, no shared endpoint, no second user, ever — the moment
  someone else depends on it, this is a different system with a different trust boundary.
- Running in the cloud. The machine is the runtime; that is the point, not a limitation to fix later.
- Publishing autonomously. Drafts go to a queue the operator reads. Nothing posts on a schedule.
- Memory that rewrites itself. Facts enter long-term memory when the operator promotes them in the
  weekly ledger, not because a loop decided something was worth keeping.
- Replacing the operator's judgement about what matters. The loops sort and summarise; ranking what
  is important is the part that is not being automated.

## kill criterion

If the morning brief is opened on fewer than 20 of the next 30 days, measured on 2026-09-22 from
the run log at `~/.coe/runs/brief.jsonl` with `node scripts/brief-open-rate.mjs --last 30`, the
scheduled loops are deleted and only ad-hoc sessions stay. An unread brief is not a tuning problem;
it is a system nobody wanted.

Second floor: if the weekly ledger takes more than 30 minutes of the operator's time for three
weeks running, measured from the operator's own timer entries, the ledger loop is removed. A
maintenance ritual that costs more than it saves is the failure mode this design is most exposed to.

## shape

`decision-support`, per the `architecture-patterns` skill: every loop produces a draft plus its
reasoning, and the operator keeps the authority to accept, edit or bin it. It is not
`process-monitoring`, despite running on a schedule — nothing here watches a stream and fires an
alert; three fixed jobs run and a person reads the output.
