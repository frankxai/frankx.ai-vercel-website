# Experience thesis — Weekly AI Architecture Review

## Promise

Give an AI architect enough verified signal to change an operating stack in one sitting. The page must distinguish a model release from distribution, governance, protocol, runtime, and connector changes.

## Evidence

- Official lab, platform, protocol, and cloud sources dated around 24–31 August 2026.
- A capped sample of 100 public commits across 10 FrankX and Starlight repositories.
- Direct repository receipts for the four engineering themes named in the editorial.
- A role-based model matrix that does not present provider benchmarks as independent measurement.

## Action

Adopt the Starlight Graph OS boundary: owned relational graph state, bounded harness adapters, one durability owner per workflow, scoped MCP/connectors, a policy-first model router, and immutable evidence receipts.

## First-frame behavior

The first 120 words state the seven-day window, what changed, and the operating decision. The hero pairs that editorial with a working XYFlow system map. A reader can select a node to see the layer’s responsibility, default technology, and non-negotiable control.

## Media and motion

The architecture map is the hero media. Exact provider and infrastructure marks identify model and connector nodes. The only authored motion is the evidence edge advancing toward the receipt ledger. Reduced-motion users receive a static edge.

## Mobile composition

Mobile does not shrink the desktop graph. It becomes a six-step operating rail with the same layer order, responsibilities, and controls. The editorial verdict precedes the rail; sources and repository receipts remain tap-accessible.
