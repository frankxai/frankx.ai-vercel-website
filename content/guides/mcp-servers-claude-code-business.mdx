For technical founders, revenue engineers, and full-stack builders wiring live tools into Claude Code: Model Context Protocol (MCP) replaces brittle glue scripts only when you curate servers tightly, guard credentials via OAuth or environment references, and cap tool-schema token bloat. On 5 November 2026 every remote endpoint in the configs below was reachable and replied `401` with an OAuth challenge, which means the server is up and waiting for you to sign in. Signing in and permissions are still on you to check. Here are the highest-signal MCP servers for **software shipping** and **business, sales, and marketing workflows**, complete with copy-paste `.mcp.json` configurations and human-gate rules.

## Try a live MCP server in 30 seconds

Before wiring anything with credentials, connect one read-only server that needs no key. frankx.ai runs one:

```bash
claude mcp add --transport http frankx https://www.frankx.ai/api/mcp
```

Then ask Claude Code to "search frankx.ai for claude code skills". It calls `frankx_search_site`, and the server answers with real pages. This is the reply it returned on 5 November 2026, trimmed:

```json
{"results":[
  {"title":"Claude Code Skills 2026: The 10 You Actually Need","type":"blog"},
  {"title":"Claude Code Plugins vs Skills: Marketplace, JetBrains & Cross-Harness Guide","type":"guide"},
  {"title":"Claude Code Templates & Starter Kit (CLAUDE.md, Skills, Settings & Hooks)","type":"guide"}
]}
```

The server exposes three read-only tools (`frankx_search_site`, `frankx_get_article`, `frankx_list_products`) and allows 30 anonymous requests a minute. Once you have seen one round trip work, add the servers below one at a time.

## Tier 1: Best MCP servers for Claude Code software engineering

Keep your core engineering `.mcp.json` focused on tools that provide **live runtime truth** unavailable from local files alone:

| MCP server | Transport | Primary engineering job | Recommended permission mode |
|---|---|---|---|
| **GitHub (`github-mcp-server`)** | Remote HTTP / Stdio | Inspect PR checks, inline review threads, issues, and workflow runs | Read + branch/PR write; protect `main` via GitHub rulesets |
| **Playwright / CDP Browser Hub** | Local Stdio -> shared CDP | Verify rendered DOM, console errors, mobile layout, and WCAG contrast | Connect to shared local browser endpoint; block production credential autofill |
| **Supabase / Neon** | Remote HTTP (OAuth) | Inspect live table schemas, `EXPLAIN` plans, RLS policies, and branch previews | Read-only role on production; read-write on ephemeral preview branches only |
| **Sentry / Grafana / Datadog** | Remote HTTP (OAuth) | Pull real stack traces, error frequencies, and p95 latency regressions | Read-only |
| **Cloudflare / Vercel** | Remote HTTP (OAuth) | Inspect preview deployment logs, Worker bindings, KV/D1 state, and build errors | Read + preview deploy; gate production DNS and billing |
| **Context7 / Official Docs MCP** | Remote HTTP | Fetch version-pinned library documentation (Next.js 16, AI SDK v6, Tailwind v4) | Read-only |

## Copy-paste `.mcp.json` configuration (zero hardcoded secrets)

Commit `.mcp.json` to your repository root using environment variable expansion (`${VAR_NAME}`) for any token-authenticated endpoint, and prefer OAuth-backed Streamable HTTP endpoints wherever vendors provide them. Set every referenced variable before you start Claude Code (here `GITHUB_MCP_PAT` and `SUPABASE_PROJECT_REF`), then confirm each server connects with `/mcp` or `claude mcp get <name>`; an unset variable can still load and then fail to authenticate:

```json
{
  "mcpServers": {
    "github": {
      "type": "http",
      "url": "https://api.githubcopilot.com/mcp/",
      "headers": {
        "Authorization": "Bearer ${GITHUB_MCP_PAT}"
      }
    },
    "sentry": {
      "type": "http",
      "url": "https://mcp.sentry.dev/mcp"
    },
    "cloudflare-observability": {
      "type": "http",
      "url": "https://observability.mcp.cloudflare.com/mcp"
    },
    "supabase": {
      "type": "http",
      "url": "https://mcp.supabase.com/mcp?project_ref=${SUPABASE_PROJECT_REF}&read_only=true"
    }
  }
}
```

> **Database note:** the old `@modelcontextprotocol/server-postgres` package is deprecated on npm and no longer in the official servers repository. Use your database vendor's own server instead. For Supabase, scope it to one project and read-only mode with `?project_ref=...&read_only=true`, as in the config above (set `SUPABASE_PROJECT_REF` first; see [Supabase's MCP security guidance](https://supabase.com/docs/guides/ai-tools/mcp)). Neon's server is `https://mcp.neon.tech/mcp`. Both sign in with OAuth. Point it at a preview branch or a read-only role, never production write access.

> **Security rule:** Never paste raw `sk_live_`, `ghp_`, or database passwords into `.mcp.json` or `~/.claude.json`. Store credentials in your OS keychain or gitignored `.env` loader and pass least-privilege read-only tokens by default.

## Keeping MCP from crowding your context

Claude Code's tool search is on by default: tool schemas stay out of context until Claude searches for the tool it needs. With `ENABLE_TOOL_SEARCH=false`, or on older models without tool search, every connected server's schemas load up front, and a large stack can fill a real share of your context before your first prompt. Tool output is the other cost: Claude Code warns when one MCP result passes 10,000 tokens and caps it at 25,000 by default (`MAX_MCP_OUTPUT_TOKENS` raises the cap). Four habits keep this in check:

1. **Scope servers per repository (`.mcp.json`)** — Keep Postgres in your backend repo, HubSpot/Search Console in your growth repo, and Figma in your design-system repo.
2. **Audit `/mcp` and `/context` weekly** — `/mcp` lists each server and its tool count; `/context` shows what is filling your context window. Disconnect servers you have not used in a week.
3. **Prefer a CLI call inside a skill for simple reads** — If a tool only wraps `gh pr checks` or a short `curl`, a skill that runs the command keeps one short description in context instead of a whole server's tool surface and credential.
4. **Migrate off deprecated proxy registries** — When self-hosting team MCP endpoints on Cloudflare Workers, follow our [remote MCP deployment guide](https://docs.starlightintelligence.ai/starlight/after-smithery).
