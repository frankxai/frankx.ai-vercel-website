Engineers and technical founders read architecture guides, run a clean notebook example, and still hit a wall the afternoon an agent touches messy retrieval chunks, external APIs, or real company money. Across the implementation guides on FrankX and the broken-system labs in [AI Architect Academy](/ai-architect-academy), I kept seeing the same pattern: projects rarely fail from weak model reasoning alone. They fail at unowned seams, such as dropped document boundaries, unvalidated MCP tool arguments, self-approved agent loops, and backup scripts nobody ever tested on a blank directory. Pick your primary track below, clone the open-source lab repository, and try one 15-minute unaided diagnosis before asking your coding agent for hints.

## Why happy-path demos fail after the chat window closes

Two empirical findings from learning science shaped how this curriculum is wired.

First, unrestricted AI assistance during practice inflates short-term output while weakening independent judgment. In a randomized field experiment of roughly 1,000 students published by [Bastani et al. in PNAS (2025)](https://www.pnas.org/doi/10.1073/pnas.2422633122), learners given an unguarded chat model scored 48 percent higher during practice exercises yet dropped 17 percent below the no-AI control group once the tool was removed. Learners using a guarded Socratic tutor that withheld direct answers gained 127 percent during practice without suffering that post-removal drop.

Second, diagnosing a broken system before reading the canonical solution builds stronger transfer than watching a polished lecture first. Across 53 studies and 166 comparisons synthesized by [Sinha and Kapur in Review of Educational Research (2021)](https://journals.sagepub.com/doi/10.3102/00346543211019105), Productive Failure showed a reliable conceptual transfer advantage (`Hedges' g = 0.36` overall, rising to `0.58` in high-fidelity designs). Struggling with a concrete fault activates your existing mental model and reveals the exact boundary you misunderstood.

<Callout type="info">
Every week in the curriculum opens with an ungraded 15-minute unaided diagnostic (`assistance = "none"`). You inspect the failing code or incident trace and record your root-cause hypothesis before Socratic `/hint` prompts or reference patterns open.
</Callout>

## Stage 1 to Stage 5: the guide-to-academy progression

Free articles explain trade-offs well, yet reading alone cannot verify that your runbook survives contact with an adversarial input. Every guide on `frankx.ai` now connects directly into a five-stage progression that raises verification rigor one rung at a time.

1. **Free guide and source call (`frankx.ai/guides`)**: Read the architectural trade-off, inspect linked primary changelogs, and check the [audience decision matrix](#decision-matrix) at the bottom of the guide.
2. **Unaided Monday diagnostic (15 minutes)**: Inspect the broken baseline or incident log without agent autocomplete. Write down the suspected failure mechanism and save its digest (`priorAttemptDigest`).
3. **Open-source terminal lab ([`frankxai/ai-architect-academy`](https://github.com/frankxai/ai-architect-academy))**: Repair the fault-injected Python or TypeScript module locally. Run the offline unit test suite until every case passes.
4. **Interactive studio mission ([`starlightintelligence.academy`](https://starlightintelligence.academy/academy/studio))**: Open the local-first browser workbench and curriculum atlas to check your architecture packet against non-compensable red gates.
5. **Weekly 20-minute peer critique and Day-7 transfer**: In cohort and community clinic sessions, a partner restates your kill criterion and rollback command cold. Seven days later, one operating constraint changes (such as strict regional VPC residency or a fourfold provider latency spike) to verify your architecture adapts cleanly.

## Human and agent dual-mode verification

Modern builders work alongside terminal agents such as Claude Code, Codex, and Antigravity. Pretending learners code in isolation makes an assessment unrealistic; letting an agent grade its own homework makes a credential meaningless.

<Diagram
  src="/images/diagrams/academy/dual-mode-verification-loop.svg"
  alt="Dual-mode verification architecture showing Human Principal reading guides and Sponsored Agent calling POST /api/mcp, separated from the Independent Examiner Kernel by an acoustic wall"
  width={1200}
  height={640}
  caption="Figure 3: Agents assist via Socratic hints and local test runs, while an acoustic wall prevents self-attestation at the examiner gate."
/>

We solve that tension by giving coding agents a clean read-only entrypoint while enforcing strict role separation at verification time:

1. **Read-only context discovery (`/api/mcp`)**: Your coding agent can query public FrankX guides, articles, and product pages directly over stateless Streamable HTTP (`POST https://www.frankx.ai/api/mcp`, documented on [`/developers`](/developers) with machine discovery at `/api/mcp/server-card`). The server exposes three read-only tools: `frankx_search_site`, `frankx_get_article`, and `frankx_list_products`. `GET` requests to `/api/mcp` return `405` by design so serverless streams never hang open.
2. **Socratic coach boundary**: Inside `frankxai/ai-architect-academy`, repository instructions configure your coding agent as a diagnostic coach. During Wednesday lab sessions, `/hint` escalates across three levels of structural questions without dumping finished answers on top of an unwritten `priorAttemptDigest`.
3. **Independent examiner and capability receipts**: An acoustic wall separates coaching hints from examination. Capability receipts in the Starlight Intelligence Academy passport surface ([`/academy/passport`](https://starlightintelligence.academy/academy/passport)) require passing offline test exit codes, zero non-compensable red-gate violations, and a reviewer identity distinct from the learner (`Reviewer != Learner`).

```bash
# 1. Register the read-only FrankX MCP endpoint in Claude Code
claude mcp add --transport http frankx https://www.frankx.ai/api/mcp

# 2. Clone the open-source labs repository
git clone https://github.com/frankxai/ai-architect-academy.git
cd ai-architect-academy

# 3. Run an offline lab test suite locally (zero API keys required)
pytest labs/01-rag-pipeline/tests/ -v
python -m unittest discover -s labs/04-trust-boundary-firewall/tests -v
python -m unittest discover -s labs/05-eval-admission-gate/tests -v
```
