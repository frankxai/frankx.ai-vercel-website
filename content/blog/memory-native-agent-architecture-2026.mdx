**TL;DR**: Memory is the difference between a clever chat and a compounding system. Separate run memory, project memory, brand memory, and evaluation memory. Wire retrieval with citations. Refuse silent amnesia.

## Why context windows are not memory

A long context is a temporary desk. Memory is a filing system with write policies.

Without structure:

- Agents re-research the same sources
- Brand voice drifts
- Failures repeat
- You cannot audit why a claim shipped

## Four memory stores

| Store | Contents | Write policy | Read pattern |
|-------|----------|--------------|--------------|
| Run memory | tool calls, scratch notes | ephemeral per job | always |
| Project memory | campaign facts, decisions | durable, versioned | by project |
| Brand memory | voice, banned phrases, personas, gravity wells | human-approved | every public draft |
| Evaluation memory | scores, failures, winning patterns | after each gate | continuous improvement |

## Design rules that keep systems honest

1. **Declarative facts, not task logs** — “User prefers concise technical posts” beats “Fixed post #42.”  
2. **Skills for procedures** — workflows live in ACOS skills; memory is not a junk drawer.  
3. **Citations for external claims** — no unsourced authority theater.  
4. **TTL for temporary context** — overnight drafts expire if not promoted.  
5. **Human approval for money and external sends** — fail closed.

## Architecture sketch

```
User brief
  → router
  → specialist agents
  → shared memory bus
  → quality gates (voice, claims, scores)
  → artifact store
  → learning writeback (evaluation memory)
```

Starlight SIS + ACOS implement this as: short session context, durable vaults, and skill-level procedures.

## Failure recovery pattern

When an agent fails:

1. Capture the failure mode in evaluation memory  
2. Do not auto-retry blindly  
3. Route to a different model or human  
4. Patch the skill if the failure repeats twice

## AEO: What is memory-native agent architecture?

It is an agent system designed around explicit memory stores and writeback loops so work compounds across sessions — not a single context window that forgets yesterday’s decisions.

## Implementation checklist (one week)

- Day 1: separate run vs brand memory  
- Day 2: add citation requirement for hub facts  
- Day 3: scoreboard for voice/strategy scores  
- Day 4: writeback of failed prompts  
- Day 5: human review queue for high-risk outputs
