# Grok Imagine Bake-off: What We Could Actually Run

**TL;DR.** On 15 August 2026 I ran three locked landscape briefs through Hermes `image_generate`. The runtime model was **`grok-imagine-image`**, not the configured `grok-imagine-image-quality`. Still-life matched. Interior added a second chair and a lamp that looks on. The droid brief returned a cream mascot, not a mechanical droid. Nano Banana, GPT Image, and FAL did not produce pixels in this run. There is no cross-model winner.

Receipt: [`/research/image-bakeoff-2026-08-14/receipt.json`](/research/image-bakeoff-2026-08-14/receipt.json) · research brief: [`/research/image-generation-bakeoff`](/research/image-generation-bakeoff)

## How Grok image generation works here

The live path is not Grok 4.6 "thinking a picture." Text and image are separate xAI surfaces under the same SuperGrok OAuth.

1. Hermes has `image_gen.provider: xai` and `image_gen.model: grok-imagine-image-quality`.
2. The session calls `image_generate` with `prompt` + `aspect_ratio`.
3. xAI returns a CDN URL. This run reported `provider: xai`, `model: grok-imagine-image`, `resolution: 1k`, `cost_in_usd_ticks: 200000000` per call.
4. The URL advertised `image/png`. The bytes were **JFIF/JPEG 1280×720**. Files were saved as `.jpg`.

That last point is a release rule: name the file from magic bytes, not from the URL.

## What is externally sourced

- xAI image API exists as Grok Imagine and is the Hermes default backend. Estate skill `hermes-image-generation` documents quality vs fast model ids.
- FrankX production image scripts: `scripts/lib/nb-image.mjs` (Gemini / Nano Banana), `gpt-image.mjs` (OpenRouter/OpenAI), `fal-image.mjs` (fal.ai).

## Locked prompts

**Still-life.** A single matte-black machined cylinder, about 12 centimeters tall, with one hairline gold ring at the midsection, standing alone on a dark slate desk. Warm sidelight from camera left, soft falloff, shallow depth of field, photoreal product photograph, 16:9. No logos, no readable text, no watermarks, no people, no screens, no UI.

**Interior.** An empty reading room at dusk: one oak table, one empty wooden chair, a tall window with cool blue twilight, an unlit brass lamp on the table, architectural photograph, 35mm lens, natural materials, quiet atmosphere, 16:9. No logos, no readable text, no book titles, no people, no watermarks.

**Droid.** A small cute modern 3D droid with compact chibi proportions, smooth cream polymer shell, a simple pixel-dot face made of two dots and a short arc, standing on a pale seamless studio floor, soft even light, collectible product render, 16:9. No humans, no skeletal robots, no logos, no readable text, no watermarks.

## What is my analysis

Grok Imagine is usable today for **quiet product stills** and **mood interiors** if you inspect count and on/off states. It is not yet a proof that it follows mechanical-droid identity. Config quality routing was not honored, so do not write "we used grok-imagine-image-quality" from `config.yaml` alone.

A comparison article that crowns Grok against Nano Banana or GPT Image would be false this week. The other lanes failed closed. That is a useful result.

## FAQ

### Is this Grok 4.6 generating images?

No. Grok 4.6 is the text/reasoning model in this session. Images came from the separate Grok Imagine backend.

### Did Grok Imagine beat Nano Banana?

Not measured. Nano Banana rejected the stored key.

### Why are the files JPEG if the URL said PNG?

The CDN advertised `image/png`. The first bytes were JFIF. We saved `.jpg`.
