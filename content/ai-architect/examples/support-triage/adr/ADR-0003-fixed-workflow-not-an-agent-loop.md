# ADR-0003: A fixed workflow, not an agent loop

## Status

Accepted

## Context

Every step of triage is known before the ticket arrives: classify, route, retrieve up to three
macros, draft, attach. There is no branch the system discovers at run time that a person did not
write down first. The `architecture-patterns` skill's three questions resolve on the first one:
the steps can be enumerated, so the shape is a fixed workflow.

The temptation is the other direction — a loop that "decides what it needs" reads as more capable
in a demo. The cost lands later, on the eval harness: a workflow is graded per step, a loop has to
be graded on trajectory, and switching shapes throws away the graded examples.

## Decision

Triage is a fixed workflow with its exit condition in code at `apps/worker/src/triage.ts:L64`
(three attempts, then stop). No step is chosen by the model. The model classifies and drafts; the
workflow decides what happens next.

## Consequences

Easier: each step is separately gradable, the run cost per ticket is predictable enough to put in
`04-roi.md` as a single figure, and an incident review can point at a step rather than a
trajectory.

Harder: a ticket that needs an unplanned step does not get one. It routes to escalations and a
person handles it, which is the intended behaviour and also the ceiling on what this system can
ever do without a redesign.

Open risk: if the queue set grows past what one classification call can hold in its instruction
set, this decision is revisited — that is a redesign, not a prompt edit.

## Alternatives considered

| Alternative | Why not |
|---|---|
| Single agent loop with tools | Unbounded spend and latency for a job whose steps are already known; the exit condition would live in a prompt |
| Sub-agents per queue | Four near-identical agents and a merge step nobody needs, for a decision one classification already makes |
| Rules only, no model | This is today's system: 31 keyword rules nobody will touch (`01-discovery.md` § 3) |

## Trust boundary

The workflow runs at T1 with T2 tool credentials. Because no step is model-chosen, the set of
tools that can be called on any path is enumerable from the source — which is what makes the tool
table in `05-trust-boundary.md` a complete list rather than a sample.
