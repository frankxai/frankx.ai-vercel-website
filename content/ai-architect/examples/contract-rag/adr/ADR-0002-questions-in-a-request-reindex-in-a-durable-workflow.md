# ADR-0002: Questions in a request, re-index in a durable workflow

## Status

Accepted

## Context

Two runs with nothing in common share this system. A question takes 34 seconds
(`fx.run.longest`) and someone is waiting for it. The monthly corpus re-index takes 41 minutes
(`fx.reindex.longest`), embeds 12,000 clauses, and nobody is waiting. Putting both in the same
execution unit means one of them is in the wrong place: either the question carries a runtime built
for a 41-minute job, or the re-index runs somewhere it can be killed halfway through and leave a
partial namespace.

## Decision

Questions run request-scoped, 34 seconds against a 300-second ceiling
(`fx.run.ceiling`), with the exit condition in code at `services/qa/src/pipeline.py:L72`. The
re-index runs as a durable workflow (`services/ingest/src/workflow.py:L19`) whose state transitions
survive a restart, and which never promotes a partial namespace.

## Consequences

Easier: a question is a request and can be reasoned about as one — timeouts, retries and latency
all behave the way the rest of the firm's services do. The re-index can take as long as it takes
and resume where it stopped.

Harder: two runtimes, two deploy paths, and two places to look during an incident. The durable
workflow's state transitions are a metered cost, small at this volume ($0.90 a month, `04-roi.md`)
and worth watching if the corpus grows by an order of magnitude.

Open risk: if a question ever needs to trigger a re-index — a newly loaded contract someone wants
to ask about immediately — that crosses the two runtimes and is a redesign, not a feature.

## Alternatives considered

| Alternative | Why not |
|---|---|
| Both in the request runtime | A 41-minute job against a 300-second ceiling; it fails, and it fails after doing partial work |
| Both in the durable workflow | Every question pays orchestration overhead and latency for a job that fits in a request |
| Cron container for the re-index | No resumption; a restart mid-run means starting over, and a partial namespace is exactly what must never be promoted |

## Trust boundary

The question path holds read-only T2 credentials for the clause index and the contract management
system. The re-index holds write access to the vector store namespaces — the only write path in the
system — which is why `swap_index_namespace` is the one irreversible tool in
`05-trust-boundary.md`'s table.
