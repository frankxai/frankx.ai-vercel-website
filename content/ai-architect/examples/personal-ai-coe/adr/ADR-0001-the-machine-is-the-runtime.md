# ADR-0001: The machine is the runtime

## Status

Accepted

## Context

Three loops run on a schedule and the longest takes 400 seconds (`fx.run.longest`). Every hosted
option — a serverless function, a managed job runner, a small always-on box — would answer the
"where does a long run live" question, and each would also add an account, a bill, a credential to
rotate, and a second place where the operator's notes exist.

The system has one user, no availability requirement, and a degraded state ("no brief this
morning") that costs nothing. Those three facts, not a preference for local software, are what
make hosting the wrong trade here.

## Decision

Loops run as scheduled tasks on the operator's own machine, registered by
`scripts/schedule/register-tasks.ps1`. There is no queue, no worker service and no cloud runtime.
A missed run is skipped, never caught up. The bound on a run is the loop's own token budget at
`packages/loops/src/run.ts:L58`, not a platform ceiling — there isn't one.

## Consequences

Easier: no hosting bill, no second copy of private notes, no credential outside the machine, and
the whole system is inspectable with a file browser.

Harder: nothing runs when the machine is off, and there is no redundancy of any kind. The memory
store lives on one disk, which makes the untested restore path (finding F1) the sharpest risk in
the design rather than an operational detail.

Open risk: if the operator ever wants the brief on a second machine, this decision is the one that
has to be reopened, and it is a redesign rather than a config change.

## Alternatives considered

| Alternative | Why not |
|---|---|
| Serverless functions on a schedule | A 400-second run near a request-shaped ceiling, plus notes leaving the machine, to solve a problem that does not exist |
| A small always-on server | A second machine to patch and a second place private notes live, for a system with no availability requirement |
| A hosted agent platform | Someone else's runtime holding the operator's memory store, and a migration the day their pricing changes |

## Trust boundary

Everything here is T0 (the operator's own files) and T1 (the repository). The only outbound
crossings are prompt content to the model provider via `packages/model/src/route.ts` and the
nightly encrypted archive to object storage via `scripts/backup.mjs`. Both are named in
`05-trust-boundary.md`; there is no third path off the machine.
