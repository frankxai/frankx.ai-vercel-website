# ADR-0002: Route by task behind one model-call seam

## Status

Accepted

## Context

Three kinds of work happen here and they have nothing in common but the word "model": ninety
mechanical summarisation runs a month, forty working sessions, and four deep reviews. `04-roi.md`
shows the shape plainly — the four deep reviews cost more than the ninety scheduled runs.

Sending all three to one model is a decision about money and latency dressed up as simplicity. The
alternative is not "use many providers", it is "have one place that decides", which is a different
thing and much cheaper to reverse.

## Decision

All model access goes through `packages/model/src/route.ts`. It holds a routing table keyed by task
kind: mechanical work to the small model, sessions to the mid model, deep reviews to the largest.
No other module imports a provider SDK. Changing the routing, adding a fallback, or swapping a
provider is an edit to one file.

## Consequences

Easier: one place for spend, one place to add a fallback when a provider is unavailable
(`01-discovery.md` § 71 records that there is none today), and a cache key that can be coherent
because there is one call path.

Harder: every new capability has to go through the seam, including experiments. That friction is
the point; an experiment that bypasses the seam is how a second call site appears.

Open risk: the routing table encodes an opinion about which work needs which model, and that
opinion ages as models change. It is re-read at the weekly deep review rather than left to rot.

## Alternatives considered

| Alternative | Why not |
|---|---|
| One model for everything | Roughly four times the monthly spend on `04-roi.md`'s volumes, for work that does not need it |
| Provider SDK imported where it is needed | Each import is a migration cost that only grows; this is the exact failure the review skill's first check looks for |
| A hosted gateway service | An account, a bill and a dependency between the operator and their own machine, to solve routing that is fifteen lines of code |

## Trust boundary

The seam runs at T1 and holds the provider credential from the machine's environment. It is the
only module that reads that credential (`rg -n "API_KEY" -tsrc` → 1 file). It writes nothing except
the run-log line, and it never reads T0 files itself — the prompt arrives already assembled from
`packages/prompt/src/context.ts`.

## Verification

```bash
rg -l "from ['\"](openai|@anthropic-ai/sdk|@google/genai)" -tsrc   # expect 1 file
rg -n "API_KEY" -tsrc                                              # expect 1 file, the seam
rg -n "routeByTask" packages/model/src/route.ts                    # expect 1 hit, L14
```
